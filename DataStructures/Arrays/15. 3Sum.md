# 15. 3Sum

## Approach

### Core Idea

The solution uses a **Sort and Two-Pointer** approach. By sorting the array first, the problem of finding three numbers that sum to zero ($a + b + c = 0$) is reduced to a series of two-pointer searches (Two Sum II) for each unique element. 

For each element `nums[i]`, we treat it as the fixed first element of the triplet. We then place two pointers, `j` (at `i + 1`) and `k` (at the end of the array), and shrink the search space based on the sum:
* If the sum is too small ($< 0$), we increment the left pointer `j` to increase the sum.
* If the sum is too large ($> 0$), we decrement the right pointer `k` to decrease the sum.
* If the sum is exactly $0$, we record the triplet and move both pointers inward, skipping any duplicate values to avoid duplicate triplets.

### Why It Works & Duplicate Avoidance

1. **Monotonicity**: Sorting ensures that the array is in non-decreasing order. This guarantees that moving the left pointer `j` to the right strictly increases (or keeps equal) the sum, while moving the right pointer `k` to the left strictly decreases (or keeps equal) the sum.
2. **Duplicate Prevention**: 
   * **Outer Loop**: `if(i > 0 && nums[i] == nums[i - 1]) continue;` ensures we do not process the same first element of a triplet twice.
   * **Inner Loop**: After finding a valid triplet, the nested `while` loops skip adjacent duplicate values for both `j` and `k` to prevent generating redundant triplets from the same starting index `i`.

### Complexity

* **Time Complexity**: $\mathcal{O}(N^2)$, where $N$ is the length of the array. Sorting the array takes $\mathcal{O}(N \log N)$ time. The outer loop runs $N$ times, and the inner two-pointer traversal takes $\mathcal{O}(N)$ time per iteration, dominating the overall complexity.
* **Space Complexity**: $\mathcal{O}(\log N)$ or $\mathcal{O}(N)$ depending on the implementation of the sorting algorithm (Java's `Arrays.sort` for primitives uses Dual-Pivot Quicksort, requiring $\mathcal{O}(\log N)$ auxiliary space). No additional memory is used other than the list required to store the output.

## Code

```Java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> arr = new ArrayList<>();
        int n = nums.length;
        Arrays.sort(nums);
        for(int i = 0; i < n - 2; i++) {
            if(i > 0 && nums[i] == nums[i - 1]) continue;
            int j = i + 1;
            int k = n - 1;
            while(j < k) {
                int sum = nums[i] + nums[j] + nums[k];
                if(sum == 0) {
                    arr.add(Arrays.asList(nums[i], nums[j], nums[k]));
                    j++;
                    k--;
                    while(j < n && nums[j] == nums[j - 1]) j++;
                    while(k > j && nums[k] == nums[k + 1]) k--;
                }
                else if(sum < 0) j++;
                else k--;
            }
        }

        return arr;
    }
}
```
