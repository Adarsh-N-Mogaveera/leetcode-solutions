# 7. Reverse Integer

## Approach

### Core Idea
The solution reverses the integer digit-by-digit from right to left. In each iteration, the last digit of $x$ is extracted using the modulo operator (`x % 10`) and appended to the reversed result `rev` after shifting `rev` to the left by one decimal place (`rev * 10`). The input $x$ is then divided by 10 to strip the processed digit. 

### Why It Works & Overflow Prevention
To prevent 32-bit signed integer overflow without using a 64-bit accumulator (like `long`), the code performs a proactive bounds check *before* multiplying `rev` by 10:
* **Upper Bound Check:** If `rev > Integer.MAX_VALUE / 10`, multiplying it by 10 will guarantee an overflow. If `rev == Integer.MAX_VALUE / 10`, it will overflow if the next digit to append is greater than $7$ (since $2^{31} - 1 = 2,147,483,647$).
* **Lower Bound Check:** If `rev < Integer.MIN_VALUE / 10`, multiplying it by 10 will guarantee an underflow. If `rev == Integer.MIN_VALUE / 10`, it will underflow if the next digit is less than $-8$ (since $-2^{31} = -2,147,483,648$).

If any of these conditions are met, the function safely aborts and returns `0`.

### Complexity
* **Time Complexity:** $O(\log_{10} |x|)$. The number of iterations in the `while` loop is proportional to the number of digits in $x$. Since a 32-bit integer has at most 10 digits, the loop runs at most 10 times, making it $O(1)$ in practice.
* **Space Complexity:** $O(1)$. The algorithm uses a constant amount of extra space to store the state of variables `rev` and `digit`.

## Code

```Java
class Solution {
    public int reverse(int x) {
        int rev = 0;
       while(x != 0) {
        int digit = x % 10;
        x = x / 10;
        if(rev > Integer.MAX_VALUE / 10 || (rev == Integer.MIN_VALUE / 10 && digit > 7)) return 0;

                if(rev < Integer.MIN_VALUE / 10 || (rev == Integer.MIN_VALUE / 10 && digit < -8)) return 0;

        rev = rev * 10 + digit;
       }

       return rev;
    }
}
```
